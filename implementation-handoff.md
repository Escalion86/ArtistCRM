# ArtistCRM landing — implementation handoff

## Перед реализацией прочитать

1. `DESIGN.md`
2. `design-contract.md`
3. `app/page.js`
4. landing-блок в `app/globals.css`
5. `tailwind.config.js`
6. `docs/ROADMAP.md`, активный пункт `SEO-T9`

## Связующие ограничения

- Не менять логотип и базовую палитру.
- Основные цвета: `#FFFEFA`, `#FFFFFF`, `#171714`, `#65655F`, `#DEDBD3`, `#9A6B27`, `#80551C`, `#F4EDE1`, `#587259`.
- Display: Futura PT 700. Body/UI: Inter Tight 400–700. Третьего шрифта нет.
- Контейнер 1240 px; поля 24 px desktop и 16 px mobile.
- Primary CTA один на смысловую зону; минимум 44 px на mobile.
- Не добавлять неон, glow, glassmorphism, абстрактную 3D-графику или новую синюю/фиолетовую акцентную палитру.

## Композиция первого артефакта

1. Header: логотип, 2–3 якоря, вход и один CTA.
2. Hero: обещание контроля заявок/клиентов/денег + реальный product preview.
3. Результаты: 4 конкретных эффекта без одинаковых «AI-карточек».
4. Маршрут: `Заявка → Контакт → Оплата → Событие/заказ`.
5. Аудитории: сначала event-профессии, затем применимость для других работающих на себя.
6. Тарифы, FAQ и финальный CTA сохраняют данные и доступность текущей реализации.

## Ассеты

- Использовать существующие логотипы из `public/img/` и `public/logo.*`.
- Product preview строить из реальных сущностей и терминов ArtistCRM; не придумывать недоступные функции.
- Не использовать stock-фотографии. Новый raster-арт требует отдельного согласования согласно `AGENTS.md`.
- Для изображений задавать `width`/`height`; LCP-ассет оптимизировать и не загружать лениво.

## Responsive и доступность

- Проверить 375, 768, 1024 и 1440 px.
- На mobile: одна колонка, hero-текст и CTA раньше preview, тарифы в вертикальном раскрывающемся формате.
- Интерактивы: semantic HTML, keyboard support, `:focus-visible`, зоны касания минимум 44×44 px.
- Поддержать `prefers-reduced-motion`; не использовать `transition: all`.
- Статусы передавать текстом/иконкой вместе с цветом.

## Первый артефакт должен доказать

- За 5 секунд понятны продукт, аудитория и три контролируемые зоны: заявки, клиенты, финансы.
- Бренд узнаваем по текущей палитре и логотипу без финтех-неона.
- Product preview выглядит как рабочий ArtistCRM, а не декоративный dashboard.
- Лендинг одинаково убедителен для ведущего/музыканта и понятен другому независимому специалисту.
- Mobile-версия не является уменьшенной desktop-композицией.

## Проверка после реализации

1. Запустить приложение и сделать визуальный QA на четырёх viewport.
2. Применить `impeccable-design-polish` без смены утверждённого направления.
3. Применить `web-design-guidelines` к изменённым JSX/CSS.
4. Запустить точечный ESLint и Lighthouse mobile; не закрывать `SEO-T9` без полевой проверки Core Web Vitals.
