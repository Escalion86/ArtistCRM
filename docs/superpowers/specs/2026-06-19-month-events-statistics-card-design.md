# Дизайн: состав плашки "Мероприятий" в статистике месяца

## Контекст

В модальном окне детализации месяца на странице статистики есть сводная плашка
"Мероприятий", которая сейчас показывает только общее количество событий месяца.
Пользователю нужно быстрее понимать состав этого числа: сколько в месяце заявок,
подтвержденных мероприятий, завершенных мероприятий и отмен.

Статистика может открываться для прошедшего, текущего и будущего месяца, поэтому
решение не должно считать месяц только "архивным" или только "плановым".

## Утвержденный подход

Используем вариант B из мокапа: общее число остается главным, под ним показывается
текстовая сводка и составная цветная полоса.

Пример:

```text
Мероприятий
18
5 заявок, 8 подтверждены, 3 завершены, 2 отменены
[amber][blue][green][red]
```

Цель полосы - быстро показать пропорции внутри общего количества. Текстовая строка
остается обязательной, чтобы числа были понятны без наведения и без зависимости от
цвета.

## Группы и правила подсчета

События месяца берутся из уже рассчитанного `details.events`, то есть из событий,
у которых `eventDate` попадает в выбранный месяц.

Группы считаются взаимоисключающими:

- `Заявки`: `event.status === 'draft'`.
- `Отменены`: `event.status === 'canceled'`.
- `Завершены`: событие не является заявкой и не отменено, а `dateEnd ?? eventDate`
  находится в прошлом относительно текущего момента.
- `Подтверждены`: событие не является заявкой, не отменено и еще не завершено по
  дате.

Статус `closed` сам по себе не является единственным признаком завершения. Закрытое
мероприятие с прошедшей датой попадает в `Завершены`. Активное мероприятие с
прошедшей датой тоже попадает в `Завершены`.

## Поведение для разных месяцев

Для прошедшего месяца основная масса событий обычно будет в `Завершены` и
`Отменены`. Если в прошедшем месяце остались `draft`, они все равно отображаются как
`Заявки`, потому что это полезный сигнал о незакрытой воронке.

Для текущего месяца возможна смешанная картина: часть событий уже завершена по
дате, часть подтверждена и еще впереди, часть остается заявками или отменами.

Для будущего месяца `Завершены` обычно равно нулю, а акцент смещается на заявки,
подтвержденные и отмененные события.

## UI

Карточка должна оставаться в текущей сетке финансовых плашек без увеличения ширины
сетки. Допускается увеличение высоты только у плашки "Мероприятий".

Визуальные элементы:

- крупное общее число `details.events.length`;
- короткая строка сводки с четырьмя числами;
- горизонтальная составная полоса, где ширина сегмента равна доле группы от общего
  количества событий месяца;
- небольшая легенда с цветом, названием и числом для каждой группы.

Предлагаемые цвета:

- `Заявки`: amber;
- `Подтверждены`: blue;
- `Завершены`: green;
- `Отменены`: red.

Если событий нет, карточка показывает `0`, строку "Нет мероприятий" и не рисует
цветную полосу с нулевыми сегментами.

Если какая-то группа равна нулю, ее можно оставить в легенде с числом `0`, но
сегмент в полосе не должен занимать видимое место. Это сохраняет стабильность
терминов между разными месяцами.

## Данные и границы модулей

Расчет состава месяца лучше вынести в helper рядом с текущей месячной статистикой,
чтобы UI не содержал бизнес-логику статусов.

Минимальный вариант:

- расширить `getStatisticsMonthDetails` полем `summary.eventStatusCounts`;
- добавить локальную функцию определения группы события по статусу и дате;
- использовать результат в `StatisticsContent` для рендера карточки.

API менять не требуется: все нужные поля уже приходят в массиве `events`.

## Ошибки и крайние случаи

Если у события нет валидной даты окончания и нет валидной даты мероприятия, оно не
считается завершенным по дате. Такое событие при статусе не `draft` и не `canceled`
попадает в `Подтверждены`.

Сравнение с текущим моментом должно использовать тот же подход, что уже применяется
в статистике для вычисляемого статуса `finished`: дата считается прошедшей, если ее
timestamp меньше `Date.now()`.

## Проверка

Нужны точечные тесты для helper'а:

- `draft` попадает в `Заявки` даже в прошедшем месяце;
- `canceled` попадает в `Отменены`;
- `active` с прошедшей датой попадает в `Завершены`;
- `closed` с прошедшей датой попадает в `Завершены`;
- будущий `active` попадает в `Подтверждены`;
- событие без валидной даты и без специального статуса попадает в `Подтверждены`.

Для UI достаточно проверить сборку/линт измененных файлов и визуально убедиться,
что карточка не ломает мобильную сетку.

## Вне рамок

В этой доработке не меняем общий фильтр статусов статистики, API статистики,
карточки мероприятий и список мероприятий месяца. Также не добавляем интерактивные
фильтры по клику на сегмент полосы.
