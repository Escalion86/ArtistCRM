# Источник регистрации и VK-аватар в профиле пользователя

## Цель

Исправить два подтверждённых расхождения в списке пользователей:

- пользователь с сохранённым `acquisition.source`, но пустым `registrationSource`, должен видеть корректный источник на карточке и в окне просмотра;
- VK-аватар, который отображается на карточке, должен отображаться и в модальном окне просмотра пользователя.

## Решение

### Источник регистрации

Добавить в `helpers/registrationSource.mjs` единый helper, который возвращает нормализованный источник с приоритетом:

1. `user.registrationSource`;
2. `user.acquisition.source`;
3. пустая строка, которую существующий formatter отображает как `Без метки`.

Использовать helper в карточке, модальном окне и статистике пользователей, чтобы все представления вычисляли источник одинаково. Некорректные или небезопасные значения должны отбрасываться существующей нормализацией.

### VK-аватары

Расширить `images.remotePatterns` в `next.config.js` отдельным HTTPS-шаблоном для поддоменов `vkuserphoto.ru`. Не отключать оптимизацию `next/image` и не разрешать произвольные внешние домены.

## Проверка

- unit-тест: `registrationSource` имеет приоритет над `acquisition.source`;
- unit-тест: при пустом `registrationSource` используется `acquisition.source`;
- unit-тест: без обоих значений сохраняется `Без метки`;
- конфигурационный тест: разрешены VK-поддомены, но не произвольные домены;
- точечный ESLint изменённых JS-файлов;
- существующие тесты атрибуции остаются зелёными.

## Вне области изменений

- заполнение источника задним числом для старых пользователей;
- перенос VK-аватаров в Escalion Cloud;
- изменение контрактов API или схемы MongoDB.
