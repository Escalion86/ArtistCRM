# Дизайн: предложение закрыть полностью оплаченное завершенное мероприятие

## Контекст

В форме редактирования мероприятия уже есть логика, определяющая, можно ли перевести событие в статус `closed`: мероприятие должно быть завершено по времени, а клиентская сумма должна быть полностью покрыта поступлениями. Сейчас эта логика используется только для ручного выбора статуса. Пользователь хочет дополнительный сценарий-подсказку при сохранении.

## Цель

После сохранения данных мероприятия система должна предложить закрыть мероприятие, если оно:

- полностью оплачено клиентом;
- завершено по дате;
- не отменено;
- еще не закрыто.

Это должно сокращать число проведенных, но забытых открытыми мероприятий.

## Решение

Реализовать post-save confirm в модалке мероприятия.

Поток:

1. Пользователь нажимает `Применить`.
2. Форма проходит текущую валидацию и сохраняется обычным способом.
3. После успешного сохранения вычисляется условие показа предложения.
4. Если условие выполнено, открывается confirm-диалог с текстом:
   `Мероприятие полностью оплачено и завершено. Возможно, стоит закрыть мероприятие?`
5. Кнопки диалога:
   - confirm: `Закрыть мероприятие`
   - decline: `Оставить открытым`
6. При confirm выполняется отдельное обновление мероприятия со статусом `closed`.
7. При decline дополнительных изменений не происходит.

## Условия показа

Диалог показывается только если одновременно выполнены все условия:

- это не заявка `draft`;
- статус после сохранения не равен `canceled`;
- статус после сохранения не равен `closed`;
- дата завершения мероприятия уже в прошлом;
- сумма всех входящих транзакций по мероприятию не меньше `contractSum`;
- если мероприятие `isByContract === true`, присутствует транзакция категории `taxes`.

Для определения завершенности используется текущая логика формы: `dateEnd || eventDate`.

## Ограничения и совместимость

- Поведение должно быть локальным для формы мероприятия в `layouts/modals/modalsFunc/eventFunc.js`.
- Серверный API не меняется.
- Существующая логика ручного выбора статуса `closed` должна остаться без изменений.
- Для нового confirm не нужно автоматически закрывать мероприятие без явного согласия пользователя.
- Для отмененных мероприятий предложение не показывается даже при полной оплате.

## Внутренняя структура

Нужно вынести вычисление условия закрытия в маленький общий helper рядом с формой или в `helpers/`, чтобы:

- не дублировать проверку между доступностью статуса `closed` и новым post-save confirm;
- покрыть поведение точечными тестами без поднятия всей модалки.

Helper должен принимать нормализованные входные данные мероприятия и транзакций и возвращать минимум:

- `canClose`;
- `isEventFinished`;
- `shouldSuggestClosing`.

## Тестирование

Нужен набор unit-тестов для helper:

- показывает предложение для завершенного и полностью оплаченного мероприятия;
- не показывает предложение, если мероприятие еще не завершено;
- не показывает предложение, если оплата неполная;
- не показывает предложение для `canceled`;
- не показывает предложение для уже `closed`;
- не показывает предложение для договорного мероприятия без `taxes`.

Дополнительно нужна ручная проверка формы:

- сохранение обычного мероприятия без выполнения условий не показывает вопрос;
- сохранение подходящего мероприятия показывает вопрос;
- `Закрыть мероприятие` переводит событие в `closed`;
- `Оставить открытым` оставляет текущий статус без побочных эффектов.
