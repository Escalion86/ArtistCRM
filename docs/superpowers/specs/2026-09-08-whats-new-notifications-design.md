# Дизайн: блок «Что нового» — уведомления пользователей о нововведениях

Дата: 2026-09-08
Статус: утверждено пользователем (хранение — БД + админка dev; прочтение — поле пользователя; вход — тост + колокольчик; архив — модалка; прочитано = открытие модалки; доставка — через `fetchProps`)

## Проблема

Пользователи кабинета не узнают о новых возможностях продукта: релизы выходят регулярно (версия bump'ится при каждом пункте roadmap), но механизма донести изменения до артиста нет.

## Цель

При входе в кабинет пользователь видит ненавязчивое уведомление о появившихся нововведениях; по клику — детали; есть постоянная точка доступа к архиву новостей. Прочтение запоминается на уровне аккаунта (все устройства). Наполнение новостей — через БД и админку dev-роли, без деплоя.

## Решение

### 1. Модель данных

Новая коллекция `news` (`schemas/newsSchema.js` + `models/News.js`):

```js
{
  title:       String,   // обязательный, до 120 символов
  version:     String,   // необязательный, «1.18.0» — бейдж версии, default ''
  items:       [String], // legacy-формат старых новостей, до 20 пунктов
  contentHtml: String,   // санитизированный TipTap HTML, до 100 000 символов
  isPublished: Boolean,  // default false — черновик не виден пользователям
  publishedAt: Date,     // default null — проставляется сервером при первой публикации
  createdBy:   ObjectId → Users,
  // timestamps: createdAt / updatedAt
}
```

- Осознанное исключение из tenant-правила: новости глобальные для платформы, `tenantId` в схеме нет. Это не упущение — записи едины для всех кабинетов.
- `usersSchema.js`: добавляется `lastSeenNewsAt: { type: Date, default: null }`.

### 2. API

Все роуты через `getTenantContext()` (авторизация обязательна), формат ошибок единый с существующими API (`NextResponse.json({ error }, { status })`).

| Метод и путь | Доступ | Поведение |
|---|---|---|
| `GET /api/news` | любой авторизованный | опубликованные новости, `publishedAt desc`, лимит 50 |
| `GET /api/news?all=1` | только `dev` | все записи включая черновики (для админки) |
| `POST /api/news` | только `dev` | создать; валидация: `title` непустой, есть содержательный `contentHtml` или legacy `items`; HTML санитизируется на сервере; при `isPublished: true` сервер выставляет `publishedAt = now` |
| `PUT /api/news/[id]` | только `dev` | редактирование; переход `isPublished: false → true` выставляет `publishedAt = now`, обратный переход `publishedAt` не трогает |
| `DELETE /api/news/[id]` | только `dev` | удаление |
| `POST /api/news/seen` | текущий пользователь | продвигает `lastSeenNewsAt` до `publishedAt` последней реально показанной непрочитанной новости (`$max`, без отката назад) |

Логика «непрочитано» вычисляется на клиенте: `publishedAt > lastSeenNewsAt` (при `null` — непрочитано всё).

### 3. Доставка данных (без отдельных клиентских запросов)

- `server/fetchProps.js`: в основной `Promise.all` добавляется `News.find({ isPublished: true }).sort({ publishedAt: -1 }).limit(50).lean()`; в payload появляется поле `news`. Запрос глобальный (без tenantId), выполняется для всех страниц кабинета — колокольчик присутствует в шапке везде. В `buildSafeDefaultPayload` добавляется `news: []`.
- `components/StateLoader.js`: кладёт `news` в новый `newsAtom` (`state/atoms`).
- `state/selectors`: `unreadNewsSelector` — фильтр `newsAtom` по `loggedUserAtom.lastSeenNewsAt`.
- `loggedUser.lastSeenNewsAt` приезжает в существующем потоке без изменений.

### 4. UI

**Тост `components/WhatsNewToast.js`** (монтируется в `CabinetWrapper`):
- Показывается, когда `unreadNews.length > 0` и в этой сессии его не закрывали (флаг — jotai-атом, живёт до перезахода на страницу).
- Плавающая карточка в правом нижнем углу; на мобильном — во всю ширину с отступами; поверх контента, ниже модалок по z-index; mobile-first.
- Содержимое: заголовок «Что нового», счётчик непрочитанных + версия последней новости, если она указана («3 нововведения · 1.18.0»), кнопка «Подробнее» и крестик. Для плашек-статусов внутри — `Notice` с подходящим `tone`.
- Крестик = скрыть до следующей сессии, прочтение НЕ засчитывается (бейдж на колокольчике остаётся).
- «Подробнее» = открыть модалку (через `modalsAtom`).

**Колокольчик в `layouts/CabinetHeader.js`** (слева от `UserMenu`):
- Иконка `faBell`, `cursor: pointer`; при непрочитанных — бейдж с числом.
- Клик открывает ту же модалку. Виден всегда — постоянная точка входа в архив.

**Модалка `layouts/modals/modalsFunc/whatsNewFunc.js`** (через `modalsFuncGenerator`):
- Заголовок «Что нового», список новостей по `publishedAt desc`.
- При открытии: фиксируется snapshot текущего `lastSeenNewsAt`; если непрочитанные есть, `POST /api/news/seen` получает `publishedAt` самой свежей из них, а `loggedUserAtom` обновляется локально (бейдж гаснет сразу, оптимистично). Пустой архив не изменяет отметку прочтения.
- Новости, опубликованные после snapshot'а, подсвечены; раскрыта только самая свежая непрочитанная новость, остальные аккордеоны свёрнуты.
- Элемент списка: бейдж версии (если есть), дата публикации, заголовок, форматированный `contentHtml` с адаптивными изображениями; для старых записей без HTML используется маркированный список `items`.

### 5. Админка новостей (dev)

- `helpers/constants.js`: новый пункт меню «Новости платформы», `href: 'site-news'`, группа 10, `accessRoles: ['dev']`; регистрация в `layouts/content/contentsMap.js`.
- `layouts/content/SiteNewsContent.js`: при монтировании грузит `GET /api/news?all=1`, список хранит локально; карточки: заголовок, версия, статус «Черновик/Опубликована» + дата, действия — редактировать, опубликовать/снять с публикации, удалить (с подтверждением). Кнопка «+ Новая новость». После каждой мутации список перечитывается.
- Модалка редактора `layouts/modals/modalsFunc/newsFunc.js`: заголовок, версия (необязательно), lazy-loaded TipTap-редактор с заголовками, начертаниями, списками, цитатой, ссылками, undo/redo и загрузкой изображений в EscalionCloud, чекбокс «Опубликована».
- После публикации новость попадает пользователям через `fetchProps` при следующей загрузке страницы кабинета — отдельной рассылки нет.

### 6. Краевые случаи и ошибки

- Первый запуск фичи: у существующих пользователей `lastSeenNewsAt = null` → первую опубликованную новость увидят все. Планируется, что первой новостью будет анонс самого блока «Что нового».
- Ошибка `POST /api/news/seen` — проглатывается молча, UI не блокируется; прочтение засчитается при следующем открытии модалки.
- Оффлайн (PWA): новости приезжают в общем payload — тост и колокольчик работают на кэшированных данных; seen-запрос не уходит, это допустимо.
- Публикация пустой новости запрещена на уровне API (`title` + содержательный форматированный текст, изображение или legacy-пункты).
- PartyCRM (`app/company`) — вне скоупа, блок только для кабинета ArtistCRM.
- Обратная совместимость mobile-клиента не затрагивается: новые API аддитивны, существующие контракты не меняются.

### 7. Проверка

- `npx eslint` точечно по всем изменённым файлам.
- Ручной сценарий: dev создаёт черновик → у пользователя ничего нет → публикация → у пользователя тост + бейдж → крестик гасит тост, бейдж остаётся → открытие модалки гасит бейдж → перезаход: тишина → вторая новость: снова тост.
- Версионирование: пункт добавляется в `docs/ROADMAP.md`; при закрытии — `[x]` + minor-bump версии (новая функциональность без breaking changes: `1.17.8 → 1.18.0`).

## Что сознательно не входит (YAGNI)

- Гранулярное прочтение по одной новости (`seenNewsIds[]`) — прочтение сплошной меткой времени.
- Push-рассылка о новостях (web push / Telegram) — отдельный возможный трек.
- Таргетирование новостей по ролям/тарифам/тенантам.
- Архив отдельной страницей в меню — архив живёт в модалке.
