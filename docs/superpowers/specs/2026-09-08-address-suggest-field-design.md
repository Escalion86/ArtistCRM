# Дизайн: умное поле ввода адреса (DaData-подсказки)

Дата: 2026-09-08
Статус: одобрено пользователем (ожидает финального ревью спеки)

## Проблема

При первом создании мероприятия пользователь видит поле «Локация» как пустой нативный `<select>` («Не указан») с кнопкой-карандашом. Непонятно, что делать дальше. Город по умолчанию подставляется незаметно внутри свёрнутой ручной формы. Нет автодополнения улиц/домов, нет координат у адресов.

## Контекст и требования (собрано в брейншторме)

- Адреса у артистов **смешанные**: 2–3 «своих» повторяющихся места + разовые адреса клиентов. Оба сценария должны быть первоклассными.
- **Mobile-first**: мероприятия чаще заводят с телефона (тач-цели ≥ 48 px, минимум полей на первом экране).
- Подключаем **DaData «Подсказки»** (бесплатный тариф 10 000 запросов/день).
- **Минимизировать обращения к DaData** (увеличенный debounce, кэши).
- Подсказки должны **корректно заполнять текущую форму адреса** (обратная совместимость объекта `address`).
- **Получать координаты** (`geo_lat`/`geo_lon`) для работы навигаторных ссылок 2ГИС/Яндекс.

## Текущая реализация (что меняем)

- `layouts/modals/modalsFunc/eventFunc.js` — поле «Локация» рендерится через `components/AddressPoolPicker.js` (строки ~1798–1811), обёрнуто в `AiFieldHighlight`. `onChange` принимает целый объект `address`, нормализуется `normalizeAddressValue`.
- `components/AddressPoolPicker.js` — `ComboBox` (нативный select) с пулом адресов + кнопка-карандаш, переключающая `showManualInput` → `components/AddressPicker.js` (ручная форма: город, улица, дом, подъезд/этаж/кв., комментарий, координаты, ссылки-навигаторы) + «Сохранить в пул».
- Пул адресов: `siteSettings.addresses` (схема `schemas/siteSettingsSchema.js`), API `app/api/site/route.js` (`addAddress`, `removeAddress`). Города: `siteSettings.towns`, `defaultTown`.
- Навигаторные ссылки: `layouts/cards/EventCard.js`, `layouts/modals/modalsFunc/eventViewFunc.js`, `server/CRUD.js` (`buildNavigationLinks`) — уже умеют координаты и `link2Gis`.

## UX-поток (одобрено)

Новый компонент **`components/AddressSuggestField.js`** заменяет `ComboBox`+карандаш внутри `AddressPoolPicker`. Сам `AddressPoolPicker` сохраняется как обёртка (интеграция с `AiFieldHighlight`, ручной формой, «Сохранить в пул»).

1. **Начальное состояние** — текстовое поле с лейблом «Локация», плейсхолдер «Начните вводить адрес или выберите из своих».
2. **Фокус на пустом поле** → дропдаун «Мои адреса» (пул из `siteSettings.addresses`, до 5 штук, строки ≥ 48 px). Если пул пуст — секция скрыта, показана подсказка «Введите улицу и дом, например: Ленинградская 12».
3. **Ввод от 4 символов** → debounce 600 мс → подсказки DaData (мягкий приоритет `defaultTown`). Совпадения из пула по введённому тексту показываются первой секцией.
4. **Выбор подсказки** → поле сворачивается в чип «Самара, ул. Ленинградская, 12» + карандаш (изменить) + крестик (очистить). Ниже — свёрнутый аккордеон «Дополнить адрес» (подъезд, этаж, кв., комментарий, ссылки-навигаторы), редактирующий тот же объект `address`, не затирая выбранное.
5. **Внизу любого дропдауна** — пункт «Ввести вручную» → существующий `AddressPicker` (fallback: офлайн, нестандартные адреса, частные дома вне ФИАС).
6. **Город по умолчанию** — мягкий приоритет (`locations_boost`), не ограничение: ввод другого города в запросе даёт подсказки по нему.

Состояние формы не меняется: один объект `address` в `eventFunc`, `onChange` наружу. Меняется только контрол.

## Серверный прокси `app/api/address/suggest/route.js` (новый)

- `POST`, защищён `getTenantContext()` (ключ DaData не уходит на клиент, endpoint недоступен анонимно).
- Env: `DADATA_API_KEY`. Задокументировать в `AGENTS.md` и при необходимости в `/docs`.
- Вход: `{ query, town? }`. Запрос к DaData `suggest/address`: `count: 7`, `locations_boost: [{ city: town }]` при наличии `town`, подсказки **только до дома** (квартиру пользователь дописывает сам).
- Ответ — нормализованный массив подсказок (см. маппинг) + координаты.
- Таймаут запроса к DaData: 4 с.
- В логи не писать `query` (адреса — чувствительные данные), только факт ошибки и HTTP-статус DaData.

## Минимизация обращений к DaData

- Debounce **600 мс**, минимум **4 символа**.
- Отмена предыдущего запроса на клиенте (AbortController).
- Клиентский кэш: Map ~50 последних запросов на сессию.
- Серверный кэш: in-memory Map, TTL 30 мин, ключ `query.toLowerCase().trim() + town` (справочные данные, не персональные).
- При стирании символов: если есть кэш более длинного запроса-префикса — фильтруем локально (best effort), новый запрос не отправляем.

## Маппинг DaData → текущая форма адреса

| Наше поле | DaData `data.` | Примечание |
|---|---|---|
| `town` | `city` \|\| `settlement` | без типа («Самара»), как при ручном вводе |
| `street` | `street_with_type` | «ул Ленинградская» — консистентно с навигаторами |
| `house` | `house` + `block` | склейка «12 к 2» при наличии корпуса |
| `latitude` | `geo_lat` | заполняем — навигаторы |
| `longitude` | `geo_lon` | заполняем — навигаторы |
| `flat`, `entrance`, `floor`, `comment` | — | не трогаем, дописывает пользователь |

Клиент прогоняет выбранную подсказку через существующий `normalizeAddressValue` → объект неотличим от ручного ввода → сохранение события, карточка, Google Calendar и навигаторные ссылки работают без изменений.

## Ошибки и деградация

- Нет `DADATA_API_KEY` → сервер отвечает `{ unavailable: true }`; клиент запоминает на сессию и работает в режиме «пул + ручной ввод» без повторных запросов.
- Таймаут/429/5xx DaData → в дропдауне строка «Подсказки временно недоступны» + всегда видимый «Ввести вручную».
- Ничего не найдено → пункт «Ничего не найдено — ввести вручную».
- Поведение «Сохранить в пул» не меняется (кнопка, как сейчас).

## Вне scope (YAGNI)

- UI управления пулом адресов (просмотр/удаление) — отдельной задачей.
- Автосохранение новых адресов в пул.
- Подсказки до квартиры.
- Тестовая инфраструктура (в проекте отсутствует).

## Проверка

Ручные сценарии: новый пользователь без пула; выбор из пула; выбор подсказки → событие сохраняется с корректными `town/street/house/latitude/longitude`; навигаторные ссылки в карточке события; ручной ввод; офлайн/недоступная DaData; узкий экран. Точечный `npx eslint` по изменённым файлам.
