# Smoke-тест: группировка входящих уведомлений мессенджеров (INT-T7)

Дата: 2026-09-04 · Версия: 1.15.3
Связанные документы: `docs/superpowers/specs/2026-09-04-messenger-notification-grouping-design.md`

Проверяется связка, которую не покрывают юнит-тесты: heartbeat → service worker → подавление, стабильный tag, throttle Expo/Android. Прогон — на staging или production после деплоя.

## Подготовка

- [ ] Залогиниться в кабинете с аккаунта с подключённым Telegram Business (и/или VK/Avito).
- [ ] Включить push-уведомления (Настройки → Уведомления), разрешение в браузере — granted.
- [ ] Обновить service worker до `artistcrm-custom-sw-v3`: перезагрузить вкладку кабинета (или DevTools → Application → Service Workers → проверить версию / сделать Update).
- [ ] Второе устройство/аккаунт для отправки сообщений «от клиента».

## 1. Подавление при открытом диалоге (Web/PWA)

- [ ] Открыть карточку клиента → диалог мессенджера.
- [ ] Отправить 2–3 сообщения от клиента подряд.
- [ ] **Ожидание:** системных push-уведомлений НЕТ вообще; сообщения появляются в диалоге.
- [ ] Подождать ~1 минуту с открытым диалогом, отправить ещё сообщение — уведомления всё ещё нет (heartbeat живёт 45 сек, интервал 15 сек).

## 2. Группировка при закрытом диалоге (Web/PWA)

- [ ] Закрыть модалку диалога (или перейти на другую страницу кабинета).
- [ ] Отправить первое сообщение от клиента.
- [ ] **Ожидание:** одно уведомление со звуком, заголовок «Новое сообщение · Telegram», текст с именем клиента и текстом сообщения.
- [ ] Не закрывая уведомление, отправить ещё 2 сообщения подряд.
- [ ] **Ожидание:** то же уведомление ОБНОВЛЯЕТСЯ (не появляются новые окна), в тексте «3 новых сообщения», обновление без звука.
- [ ] Клик по уведомлению → открывается кабинет (мероприятие или клиенты).

## 3. Сброс после прочтения

- [ ] Открыть диалог (прочитать), закрыть.
- [ ] Отправить новое сообщение.
- [ ] **Ожидание:** уведомление снова «первое в серии» — со звуком, без счётчика (или со счётчиком 1).

## 4. Throttle на Android (Expo)

- [ ] Закрытый диалог, Android-устройство с установленным приложением.
- [ ] Отправить 3+ сообщения подряд с интервалом ~10–20 сек.
- [ ] **Ожидание:** на Android приходит не более 1 push в 2 минуты на этот чат (web при этом обновляется каждый раз).
- [ ] Через 2+ минуты отправить ещё сообщение → push приходит снова.

## 5. Регрессия: записи звонков и разные клиенты

- [ ] Пришла запись звонка (Novofon) → уведомление «Получена запись звонка · …» приходит как раньше, отдельным уведомлением.
- [ ] Написали два РАЗНЫХ клиента → два независимых уведомления (группировка — per-чат, не глобальная).

## Если что-то не так

- Уведомления дублируются окнами → проверить версию SW (должна быть v3) и что tag в payload стабильный (DevTools → Application → Service Workers → push-лог / `self.registration.getNotifications()`).
- Подавление не работает при открытом диалоге → проверить, что SW контролирует вкладку (`navigator.serviceWorker.controller` не null) и что heartbeat доходит (console в SW: входящие `messenger:active`).
- Android шлёт каждый раз → проверить поле `lastPushAt` на документе чата в Mongo и время сервера.
