# ArtistCRM Release Smoke Runbook

Дата: 2026-06-07.

Локальный прогон от 2026-09-10, команды и ограничения: [отчёт](RELEASE_CHECK_2026-09-10.md). Он не закрывает проверки реальных провайдеров и устройств ниже.

Продолжение от 2026-09-11: [параллельные платежи и начисление баланса](RELEASE_CHECK_2026-09-11.md), общий набор 24/24. Реальные платежи не выполнялись.

Цель: быстро проверить production или staging-clone перед официальным анонсом. Это не заменяет автотесты, но снижает риск провала первого пользовательского сценария.

## Правила прогона

- Использовать отдельного тестового пользователя и отдельный tenant.
- Не использовать реальные данные клиентов.
- Для платежей использовать минимальные разрешенные суммы и тестовые/контролируемые аккаунты провайдеров.
- Все найденные ошибки фиксировать с URL, временем, пользователем, payload/скриншотом и ожидаемым результатом.
- После прогона удалить тестовые заявки, клиентов, транзакции, webhook-подключения и тестовую базу restore-check.

## 1. Production sanity

- [ ] `https://artistcrm.ru` открывается по HTTPS.
- [ ] `http -> https` работает.
- [ ] `www.artistcrm.ru -> artistcrm.ru` работает или принято решение оставить оба домена.
- [ ] `/robots.txt` отдает корректный файл.

Ожидаемый результат: публичная часть доступна, canonical-домен понятен, поисковые файлы отдаются.

## 10. Go/no-go

Запуск разрешен, если:

- нет 500 на базовых пользовательских маршрутах;
- регистрация, первый вход, заявка, клиент, мероприятие, транзакция и документ работают;
- хотя бы один реальный платежный сценарий прошел от создания до webhook/sync;
- backup/restore проверен;
- production env очищен, секреты перевыпущены;
- известные ограничения зафиксированы в тексте анонса и support-шаблонах.

Запуск переносится, если:

- есть ошибка tenant isolation;
- платеж может быть начислен неверно или повторно;
- невозможно восстановить backup;
- невозможно зарегистрироваться или создать первую заявку;
- webhook публичной интеграции принимает запрос без ожидаемого tenant secret/token.
