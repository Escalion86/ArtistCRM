# UX-аудит кабинета ArtistCRM

Дата: 2026-09-03. Метод: статический анализ кода (без запуска), линза mobile-first.
Скоуп: кабинет Web/PWA (`/cabinet/*`). Онбординг-мастер не аудирован — он сейчас в доработке (codex).

## Резюме

Кабинет функционально богатый, но есть системные UX-проблемы в трёх зонах:

1. **Первый старт и пустые состояния** — новый пользователь встречает тупики вместо приглашений к действию. Это напрямую бьёт по главной боли «начать».
2. **Мобильная навигация** — главное действие (создать заявку) спрятано за иконкой «+» с выпадающим меню; каждый переход между разделами требует открыть бургер.
3. **Консистентность** — две системы акцентных цветов, опечатки, мёртвый legacy-бренд Cigam, техничные детали (raw JSON Google Calendar) торчат в пользовательский UI.

Рекомендуемый первый пакет работ — раздел «Спринт UX-1» в конце документа.

## P0 — критично для активации и мобильных сценариев

### UX-01. Пустые состояния — тупики без действия, с опечаткой

- `layouts/content/EventsContent.js:1718` — текст «Для выбранных фильтьров мероприятий пока нет» (опечатка «фильтьров») показывается **всегда**, когда список пуст: и когда фильтры активны, и когда у нового пользователя просто нет ни одной заявки. Нет кнопки «Создать заявку».
- `layouts/content/ClientsContent.js:244` — «Клиенты не найдены» одинаково при пустой базе и при пустом поиске; нет CTA «Добавить клиента».
- `layouts/content/TransactionsContent.js:342` — «Транзакций пока нет» без CTA.
- `components/EmptyState.js` — компонент не поддерживает действие (кнопку).

**Импакт:** первый экран нового пользователя после мастера настройки — пустой список с текстом про фильтры. Прямой удар по активации.
**Решение:** расширить `EmptyState` (иконка, заголовок, подсказка, primary-кнопка), различать состояния «нет данных вообще» vs «нет результатов по фильтрам/поиску» (во втором случае — кнопка «Сбросить фильтры»).

### UX-02. Главное действие спрятано за иконкой «+»

- `layouts/content/EventsContent.js:214-283` — создание заявки/мероприятия/голосового черновика доступно только через выпадающее меню у маленькой иконки (36px). На телефоне это единственная точка входа в главный сценарий продукта.
- FAB в кабинете закомментирован (`app/cabinet/[page]/cabinet.js:114`).

**Импакт:** мобильный пользователь не видит словом, что здесь можно «Создать заявку»; голосовой ввод (ключевая фича) скрыт на втором уровне меню.
**Решение:** на мобильном — явная primary-кнопка «+ Заявка» в шапке списка или возврат FAB с меню; на десктопе оставить DropDown, но с текстовой подписью.

### UX-03. Два авто-попапа сразу после входа на страницу

- `layouts/content/EventsContent.js:965-1015` — при заходе на «Предстоящие» автоматически открывается модалка «Требует внимания» (раз в день по подписи), а следом может открыться вторая модалка «Просрочено ожидание задатка».

**Импакт:** пользователь каждый день начинает работу с закрытия 1–2 модальных окон. Модалка как ежедневный ритуал — интрузивный паттерн.
**Решение:** не открывать автоматически; показывать ненавязчивый бейдж/плашку над списком (она уже частично есть — кнопка «Требует внимания» с счётчиками). Авто-показ оставить максимум для просрочки и только если пользователь ещё ни разу не открывал центр за день.

### UX-04. Десктопный сайдбар не скроллится колесом мыши

- `layouts/SideBar.js:306-319, 342-348, 418-449` — у меню `overflow-y-hidden`, прокрутка реализована программно кнопками-стрелками (`scrollTop` вручную). Колесо мыши и тачпад жесты не работают, нативного скроллбара нет.

**Импакт:** на десктопе меню с 10+ группами (а у dev/admin их много) фактически непрокручиваемо привычным способом — пользователь обязан целиться в стрелки.
**Решение:** вернуть `overflow-y-auto` с тонким стилизованным скроллбаром, стрелки удалить.

### UX-05. Мобильная навигация: каждый переход = бургер

- Основные разделы (Предстоящие, Клиенты, Звонки, Транзакции) на телефоне доступны только через drawer 85vw (`layouts/SideBar.js:276-279`). Нижней навигации нет.

**Импакт:** phone-first сценарий «пришла заявка → позвонил → записал» требует лишних касаний; между разделами нет быстрого переключения.
**Решение:** нижняя навигационная панель на мобильном: Предстоящие / Клиенты / [+] / Финансы / Меню. Бургер остаётся для остального.

### UX-06. UserMenu открывается по hover

- `layouts/UserMenu.js:140-161` — меню пользователя открывается по `onMouseOver` с хрупким флагом `turnOnHandleMouseOver`. На десктопе меню всплывает при случайном наведении и перекрывает контент; hover-открытие недоступно с клавиатуры.

**Решение:** открытие только по клику (стандартный dropdown с aria-expanded), hover-логику удалить.

## P1 — консистентность, доверие, форма мероприятия

### UX-07. Опечатки в пользовательском тексте

- `layouts/content/EventsContent.js:1718` — «фильтьров».
- `layouts/modals/modalsFunc/eventFunc.js:2200` — «Пока никаких транзакций небыло».

### UX-08. Мёртвый legacy-бренд Cigam

- `app/cabinet/[page]/cabinet.js:92` — `<title>Cigam.ru - Кабинет…</title>` (через `next/head`, что в App Router не работает — код мёртвый, реальный title задаёт `metadata` в `page.js`).
- `app/api/iii.js` — целиком мёртвый legacy-модуль: не является роутом (нет `route.js`), нигде не импортируется, содержит захардкоженный Telegram `chat_id` и тексты «Заявка на cigam.ru».

**Решение:** удалить `iii.js` и блок `Head` из `cabinet.js`.

### UX-09. Две системы акцентных цветов в кабинете

- Дизайн-контракт и токены: бронза `--ui-primary: #9a6b27` (`app/globals.css:42`).
- Но фильтры используют оранжевый `#c75f00` (`globals.css:479-497`), счётчик в шапке — синий `#315da8` (`globals.css:449-453`, `layouts/CabinetHeader.js:43`).

**Импакт:** визуальный шум, расхождение с `DESIGN.md`. **Решение:** свести акценты к `--ui-primary`, семантические цвета (зелёный/красный) оставить.

### UX-10. Календарь месяца начинается с воскресенья

- `helpers/constants.js:145` — `DAYS_OF_WEEK = ['ВС', 'ПН', …]`, сетка в `EventsContent.js:437-471` строится от `getDay()` (воскресенье = 0). Для РФ привычен понедельник; Яндекс/Google-календари пользователя начинаются с ПН — диссонанс при сверке.

### UX-11. Кнопка переключения «список/календарь» показывает текущий режим, а не целевой

- `layouts/content/EventsContent.js:1591-1606` — в режиме списка на кнопке иконка списка (`ViewListIcon`), хотя клик переключает в календарь. Tooltip правильный («Показать календарь»), иконка — нет.

### UX-12. Просмотр мероприятия: безличный заголовок и мёртвые пропсы

- `layouts/modals/modalsFunc/eventViewFunc.js:854-858` — заголовок модалки всегда «Мероприятие» (не тип события/адрес/дата); `confirmButtonName: 'Записаться'` — мёртвый проп из старого продукта (кнопка не рендерится, но сигнализирует о legacy).

### UX-13. Ошибки формы мероприятия не видны на других вкладках

- `layouts/modals/modalsFunc/eventFunc.js` — обязательный «Клиент» находится на вкладке «Клиент и Контакты», а `ErrorsList` выводится только внизу вкладки «Общие» (строка 1844). Если при сохранении не заполнен клиент, пользователь на первой вкладке видит текст ошибки, но не понимает, где поле; на самих вкладках индикаторов ошибок нет.

**Решение:** бейдж с числом ошибок на заголовках вкладок + авто-переход к первой вкладке с ошибкой при сабмите.

### UX-14. Вкладка «Ответ Google Calendar» с raw JSON в форме пользователя

- `layouts/modals/modalsFunc/eventFunc.js:2385-2406` — технический ответ API показывается отдельной вкладкой в редакторе мероприятия. Для диагностики синхронизации достаточно иконки ошибки в карточке + текста в настройках интеграции.

### UX-15. Фиксированная высота виртуализированных карточек

- Списки используют `react-window` с фиксированной высотой строки: события 194/206px (`EventsContent.js:527`), клиенты 178/190px, транзакции 176/188px. Карточки с `min-h-[160px]` и переносами контента могут обрезаться или оставлять пустоту на промежуточных ширинах.

**Решение:** замерять реальную высоту (react-window v2 поддерживает динамические строки) или зафиксировать состав карточки так, чтобы высота была гарантирована.

## P2 — техдолг, влияющий на скорость UX-итераций

- UX-16. Большое количество закомментированного кода в ключевых файлах (cabinet.js, SideBar.js, UserMenu.js, eventViewFunc.js) — шум при ревью.
- UX-17. Смешанная иконография MUI Icons + FontAwesome в одних тулбарах (`EventsContent.js` шапка: MUI-фильтр + кастомный «+»).
- UX-18. `next/head` и `<Link shallow>` — наследие Pages Router, в App Router не работают (мёртвые пропсы).
- UX-19. Меню сайдбара: названия групп в `uppercase tracking-wide` с иконками 2x — крупный визуальный вес, на длинных списках выглядит тяжело.
- UX-20. Бейдж счётчика >99 показывает «!» (`SideBar.js:97`) — теряется информация; лучше «99+».

## Спринт UX-1 (предлагаемый первый пакет, ~1 итерация)

Фокус: активация нового пользователя + мобильная навигация. Без breaking changes, patch/minor версия.

1. **EmptyState 2.0**: иконка + заголовок + подсказка + CTA; применить на Мероприятиях («Создать заявку», и отдельный текст «Ничего не найдено по фильтрам → Сбросить»), Клиентах, Транзакциях. Заодно опечатки UX-07.
2. **Мобильная primary-кнопка создания** на экране мероприятий (текст «+ Заявка» вместо голой иконки; меню с голосом/текстом сохранить).
3. **Убрать авто-попапы** при входе (UX-03), оставив бейджи.
4. **Сайдбар: нативный скролл** вместо стрелок (UX-04), UserMenu по клику (UX-06).
5. **Чистка legacy**: удалить `app/api/iii.js`, `Head` из cabinet.js, мёртвый `confirmButtonName: 'Записаться'` (UX-08, UX-12).
6. **Календарь с понедельника** (UX-10) + правильная иконка переключения вида (UX-11).
7. **Единый акцент** `--ui-primary` для фильтров и счётчиков (UX-09).

Отдельными следующими итерациями: нижняя мобильная навигация (UX-05), ошибки вкладок формы мероприятия (UX-13), динамическая высота карточек (UX-15), вкладка «Ответ Google Calendar» → в диагностику (UX-14).
