# AI-импорт из Google Calendar

## Пользовательский сценарий

Импорт открывается отдельной страницей из пункта `Настройки → Импорт` бокового меню и доступен тарифу, в котором одновременно включены Google Calendar и ИИ.

1. Пользователь подключает отдельный Google-аккаунт для импорта и выбирает в нём календарь-источник.
2. Указывает период или выбирает быстрый вариант на 3/6 месяцев.
3. Нажимает «Найти мероприятия» и бесплатно получает список событий.
4. Выбирает события, видит количество AI-обработок, ориентировочную стоимость и доступный баланс.
5. Запускает импорт. Интерфейс отправляет события пакетами по 10 и показывает прогресс.
6. Созданные мероприятия открываются как черновики для ручной проверки.

Повторный запуск безопасен: событие, уже связанное с тем же Google event ID, пропускается.

Подключение импорта полностью независимо от Google Calendar в разделе «Интеграции»: допускаются разные Google-аккаунты и разные календари. Для импорта отдельно хранятся OAuth-токены, выбранный календарь и дата подключения. Переподключение или отключение импорта не меняет направление экспорта и синхронизации мероприятий CRM, а отключение интеграции не прерывает импорт.

## Правила заполнения

- Дата и время всегда берутся из Google Calendar. Для события на весь день используется 12:00 в часовом поясе пользователя и стандартная длительность мероприятия.
- Поле `location` события Google имеет приоритет. Если оно пустое, адрес ищется в названии и описании.
- Название и описание анализируются для определения типа мероприятия, услуг, клиента и контактов, договорной суммы, ожидаемого задатка, договорного признака, финансового комментария и полезного остатка описания.
- Существующий клиент ищется по явному контакту или однозначному совпадению имени. При явном контакте без совпадения создаётся новый клиент; если имени нет, его заменяет контакт.
- При неоднозначном имени клиент автоматически не выбирается, а в черновике сохраняется предупреждение.
- Финансовые транзакции импорт не создаёт. Распознанные суммы остаются полями черновика и требуют проверки.
- Отменённые события и события без ID/даты не импортируются.

Поля, заполненные ИИ, временно подсвечиваются в форме. Подсветка отдельного поля исчезает после его ручного изменения; после первой проверки и сохранения подсветка и служебные предупреждения очищаются.

## Ограничения и стоимость

- Максимальный период одного просмотра: 366 дней.
- За один запуск пользователь может выбрать до 100 событий.
- Один серверный пакет содержит не более 10 событий.
- ИИ вызывается только для событий с непустым описанием. События без описания создаются по данным Google и безопасным детерминированным подсказкам без AI-расхода.
- При встроенном ИИ ArtistCRM до запуска показывается ориентировочная стоимость и баланс, а после завершения — фактическое списание.
- При собственном ключе AI-провайдера ArtistCRM не списывает средства; расходы определяются провайдером пользователя.

Предварительная смета рассчитывается по числу выбранных событий, которым нужен ИИ, и текущему порогу стоимости одной операции. Фактическая сумма может отличаться, так как зависит от объёма текста и ответа модели.

## API

### Предварительный просмотр

`GET /api/events/google-import?timeMin=<ISO>&timeMax=<ISO>`

Возвращает календарь, кандидатов, признаки дубля/отмены/AI-обработки, лимиты и смету. Данные в CRM не изменяются.

### Импорт пакета

`POST /api/events/google-import`

Тело запроса:

```json
{
  "timeMin": "2026-08-09T00:00:00.000Z",
  "timeMax": "2027-02-09T23:59:59.999Z",
  "eventIds": ["google-event-id"],
  "groupId": "uuid-одного-пользовательского-запуска"
}
```

Сервер повторно получает выбранные события у Google, проверяет tenant, тариф, подключение, лимиты и дубли, затем создаёт черновики. `groupId` объединяет AI-расходы нескольких пакетов одного запуска.

## Конфиденциальность

OAuth-токены аккаунта импорта хранятся отдельно от токенов синхронизации. Для импорта запрашивается доступ Google Calendar только на чтение. В AI-провайдер передаются название и описание только выбранных пользователем событий и минимальный справочный контекст услуг и клиентов, необходимый для сопоставления. OAuth-токены, дата/время и Google location в AI-запрос не передаются как данные для определения этих полей. Персональные данные нельзя записывать в серверные логи.
