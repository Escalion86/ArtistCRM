# AI-импорт мероприятий из файла

Вход: `Настройки → Импорт и экспорт → Импорт → Из файла`.

Доступ ко всему мастеру и его API (включая загрузку, список и открытие сохранённых импортов) разрешён только при `allowAi` в действующем тарифе. Баланс и личный ключ провайдера не заменяют тарифный доступ. Фоновая обработка повторно проверяет право перед AI-запросом и созданием мероприятия: при отключении ИИ останавливается с возвратом остатка резерва. Уже созданные мероприятия остаются доступны для обычной проверки и редактирования.

## Форматы и ограничения

- Только **XLSX, CSV, TXT, DOCX**. PDF, изображения, сканы, XLS, DOC и документы с макросами не поддерживаются.
- Один файл до 5 МБ; распакованный OOXML до 20 МБ; до 80 000 символов, 1500 непустых строк и 100 мероприятий. До 20 сохранённых импортов пользователя.
- XLSX: листы, строки, текст и сохранённые значения формул. Формулы не выполняются. Ссылки не открываются. Объединённые ячейки отмечаются предупреждением.
- DOCX: основной текст и таблицы. Встроенные изображения пропускаются с уведомлением; OCR отсутствует.
- CSV: запятая, точка с запятой или табуляция, кавычки и многострочные ячейки. TXT/CSV: UTF-8, UTF-16 с BOM, Windows-1251.
- Проверка формата и извлечение текста выполняются до AI-запросов и бесплатно. Полный бинарный оригинал не сохраняется.

## Три этапа

1. **Анализ и уточнения.** После загрузки показывается предел расходов на анализ и доступный баланс. Только явный запуск резервирует деньги и отправляет извлечённый текст провайдеру. ИИ возвращает описание структуры, правила, до трёх примеров, до трёх вопросов и записи с привязкой к исходным строкам. Несколько мероприятий в одной строке допустимы при точных непересекающихся цитатах. Строки, не отнесённые к мероприятиям, доступны для проверки. Пользователь отвечает на вопросы, при необходимости добавляет общее пояснение и выбирает записи.
2. **Стоимость.** Расчёт на основе выбранных записей, согласованных правил и объёма текста не вызывает ИИ. Оценка основана на истории стоимости операций с запасом и масштабированием по объёму; до накопления истории используется существующий резервный ориентир биллинга. Это оценка, а не точный тариф провайдера. Показаны стоимость анализа, бюджет оставшейся обработки, баланс и недостающая сумма. При нехватке денег кнопка запуска недоступна. Сервер повторно проверяет баланс при подтверждении.
3. **Импорт.** После подтверждения резервируется весь бюджет. Сервер обрабатывает записи последовательно, сохраняет ответы ИИ и прогресс. Создаются черновики с `importedFromFile: true`, `fileImportChecked: false`, источником, предупреждениями и подсветкой AI-полей. Проверка доступна независимо от тарифа Google Calendar. После проверки пользователь включает «Импорт из файла проверен» и сохраняет мероприятие.

Успешное распознавание не означает автоматическую проверку. Непроверенные файловые мероприятия не отправляются в Google Calendar: запрет расположен также в общем `updateEventInCalendar`, поэтому охватывает web/mobile и другие вызывающие маршруты. Календарный признак сохраняет прежнюю семантику для старых мероприятий.

## Данные и повторы

- Неопределённая дата/год: запись откладывается, случайная дата не подставляется. Год должен подтверждаться точной цитатой источника или ответа. Дата без времени получает 12:00 в часовом поясе пользователя и предупреждение.
- Клиент подбирается по явному контакту или однозначному имени. При контакте без совпадения создаётся клиент; неоднозначное имя требует ручной проверки. Услуги сопоставляются с существующими.
- Финансовые транзакции не создаются. Суммы и сведения об оплатах сохраняются в полях/финансовом комментарии для проверки.
- Повторная загрузка того же содержимого открывает сохранённый импорт, даже если файл переименован. Уникальный индекс `tenantId + fileImportKey` предотвращает повторное создание по одной записи источника.
- Совпадение клиента и точного времени с существующим мероприятием помечается возможным дублем и пропускается; автоматическое объединение не выполняется.
- Результат каждого платного запроса сохраняется вместе со списанием. Если создание мероприятия не удалось, повтор использует сохранённые поля. Изменение ответов сбрасывает поля только у незавершённых записей: новая интерпретация требует нового расчёта и подтверждения.
- Запрос с неизвестным исходом после аварийной остановки не повторяется автоматически. Внешняя стоимость, которую не удалось достоверно учесть, не списывается с пользователя; новая попытка требует подтверждения.

## Баланс и предел расходов

Резервирование всего этапа, учёт расхода и возврат выполняются атомарными обновлениями одного документа владельца. Поддерживается standalone MongoDB. Деньги резерва исключены из доступного баланса для других операций. Ровно достаточного баланса хватает.

Закрытый бюджет возвращается только один раз. Расход учитывается в целых копейках; фактическая стоимость AITunnel умножается на зафиксированную наценку. Списание ограничено остатком согласованного бюджета. Если последний запрос дороже остатка, превышение не списывается с пользователя и отражается в `uncoveredKopecks`; следующий платный запрос не запускается. Неизвестная стоимость останавливает обработку без списания за этот запрос. Полученный, но некорректный ответ модели может иметь реальную стоимость: она остаётся в журнале.

История `AiUsage`/`Payments` использует `file_analysis`, `file_import` и общий `groupId` импорта. Данные для восстановления хранятся в `Users.aiFileImportBudgets` с `select: false` и не включаются в обычные ответы пользователя.

При личном ключе баланс ArtistCRM не используется; расходы определяет личный провайдер. Указанный предел баланса ArtistCRM к расходам личного ключа не применяется.

## Фоновая работа и хранение

Прогресс находится в MongoDB, а не в браузере. `after()` запускает ограниченный по времени проход; lease предотвращает параллельную обработку одного задания. Открытая страница опрашивает состояние и продолжает авторизованное задание. Для продолжения больших импортов при закрытом браузере **обязателен production cron**:

- Каждую минуту: `POST /api/events/file-import/worker`.
- Заголовок: `Authorization: Bearer <CRON_SECRET>`.
- Один вызов планирует до двух заданий; повторные вызовы безопасны. Runtime маршрутов: Node.js, до 300 секунд. Таймаут одного AI-запроса — 60 секунд.
- Без cron текущий проход завершается, но оставшаяся очередь продолжится только при открытии сохранённого импорта.

Извлечённый текст, ответы и временные результаты хранятся до 30 дней. Worker очищает истёкшие неактивные задания после освобождения резерва и восстановления журналов. Поля источника, уже сохранённые в мероприятии, остаются частью мероприятия. Очистка не должна удалять активные резервы через TTL.

## API

- `POST /api/events/file-import`: multipart `file`, необязательный `note`; проверка/извлечение и предварительная оценка анализа, без ИИ.
- `GET /api/events/file-import`: последние сохранённые импорты текущего tenant.
- `GET /api/events/file-import?id=...`: состояние, баланс, расходы, исходники и результаты. Активное авторизованное задание получает очередной фоновый проход.
- `POST /api/events/file-import/[id]`: `action` — `analyze`, `quote`, `start`, `refresh`, `stop`, `release`. Для платного запуска обязателен текущий `quoteId`; для `quote` — `answers` и `selectedIds`.
- `POST /api/events/file-import/worker`: служебный cron с серверным секретом; у каждого обрабатываемого задания сохраняется собственный tenant.

Все пользовательские операции используют `getRequestContext()` (web через `getTenantContext()`, mobile через Bearer) и tenant-фильтры. Неподдерживаемые файлы отклоняются до ИИ. Содержимое и ошибки провайдера не выводятся в серверные логи/пользовательские ответы как необработанные данные.

## Проверка

```powershell
node --test server/fileImport.test.mjs server/aiChatCompletion.test.js
$env:FILE_IMPORT_TEST_MONGO_URI='mongodb://127.0.0.1:27017'
node --test server/fileImportBudget.integration.test.mjs
node tests/file-import/http.integration.mjs
```

Mongo/HTTP-проверки создают отдельную БД с префиксом `codex_file_import_test_` и удаляют только её. HTTP-проверка запускает локальный mock ИИ и изолированный Next dev; реальный ИИ и данные основного приложения не используются.
